# 前端像素复刻排查指南

> 适用问题类型：Qt Widgets 前端与 `05_Single_HTML_Frontend_Reference.html` / `04_UI_Design_Mockup.png` 的逐像素对齐差异排查。
> 更新记录见文末。

## 问题描述

把 `src/player/`（MainWindow.cpp + UiKit.h）的 Qt Widgets UI 做到与参考 HTML 设计稿「同尺寸并排比对无可见差异」。参考稿为 1280x800 的 showcase 页面：顶部 `.app-window` 是应用窗口（宽 1280，高约 615px），底部是特性卡区（复刻范围外）。

## 已建立的有效方法（✅）

- ✅ 截图机制：`RCP_DEMO_ONLY=1` + `RCP_SNAPSHOT=<png>` + `RCP_SNAP_T1/T2` 抓 1280x800 逻辑界面；`RCP_NO_CAPTION=1` 跳过 worker。脚本 `tools/run_snap.ps1`。
- ✅ 参考渲染：Edge 无头渲染参考 HTML 到 1280x800。**失败尝试 ❌**：`--headless=new --virtual-time-budget=8000` 在 PowerShell 下超时未出图（进程挂起）。**成功方法 ✅**：复用上一轮已生成的 `out/e2e-verify/ref-1280.png`（HTML 未变化，渲染结果一致）；如需重渲改用 `--headless=old` 或带超时并确认进程退出。
- ✅ 缩放对齐：应用快照 1920x1200（150% DPI）用 PIL LANCZOS 缩到 1280x800，再按参考稿布局列宽（1280 断点：左轨 218 / 视频区 218-958 / 设置面板 958-1280）裁剪各区域并排（ref 左 / ours 右），脚本 `tools/make_compare.py`、`tools/compare_regions.py`、`tools/compare_deck2.py`、`tools/zoom_regions.py`。
- ✅ 像素级确认：PIL 采样目标行/区域的精确颜色与字形高度，判断图标有无、字体大小、滑块颜色等（OCR 描述不可尽信）。
- ✅ 差异清单逐项修复后，重新 `tools/run_snap.ps1` 出图 → 重新并排比对 → 清零才算 DONE。

## 关键认知（避免重复踩坑）

1. **参考稿 1280 断点**：`@media (max-width:1320px)` 下左轨 238→218、设置面板 344→322、标题动作按钮隐藏文字标签只留图标。应用 `applyBreakpoint()` 已实现，比对/裁剪必须按断点后的列宽来。
2. **应用窗口高度 vs 参考 app-window 高度不同**：参考 app-window 仅约 615px（下方是 showcase 特性卡区），实际应用窗口是完整 800px。因此视频区/转写区/左轨底部更高，控制条在 y≈692（参考在 y≈507）。这是固有差异，不修；比对各组件内部样式/相对锚点（字幕 13% 底、波形 calc(13%-31px)、徽标 top17/right18）。
3. **子像素字体渲染差异**（浏览器 vs Qt）不可消除，属于可接受范围；只对齐字号/字重/颜色/间距。
4. OCR 对图标的识别不可靠，用 PIL 采样判定。

## 本轮（字幕轮，2026-09-04）：字幕字号被全局 QSS 覆盖 + 真实视频字幕验证 + 唯一字幕路径

### 问题描述
- 用户：①"还是和设计图不一样，起码视频播放的字幕就不对"；②"不要只看样例视频，还要打开我历史播放测试的视频，这两个字幕居然还能不一样"；③"这两个都是字幕，怎么能有两个路径？不应该只有一个字幕路径吗"。

### 根因分析（❌ 尝试 → ✅ 定位）
- ❌ 尝试 1（猜测 mpv 或 WorkerSupervisor 渲染差异）：逐像素扫 demo 与真实字幕，误以为"真实字幕更大"。
- ✅ 根因（字号）：**全局 QSS `kAppQss` 第 67 行 `QWidget{font-size:14px}` 优先于程序 `setFont(36px)`**（Qt 样式表字号优先级高于 setFont），字幕被压成 14px。`setFontSizePx` 用 `setPixelSize`+`setFont` 无法覆盖 QSS。
- ✅ 修复：`CaptionLabel::setFontSizePx` 在控件**自身 stylesheet** 声明 `font-size:%1px`（自身规则优先于应用级规则；其余字体属性仍由 setFont 提供）。参考规格：final 36px 白字四向 ±2px 描边 rgba(0,0,0,.94)+阴影、partial≈29.5px 半透明灰 rgba(225,228,234,.67)、两行间距 5px、画面底部 13% 锚定、波形在字幕下方。
- ✅ 验证：demo 快照 capfix1.png + 真实播放 real3_cap.b.png，经 cap_strip_v3/cap_final_v2 同逻辑比例并排确认 final≈36px、partial≈29.5px，与参考稿一致。

### 真实视频字幕验证方法（✅，关键）
- **不要只跑 demo（RCP_DEMO_ONLY）**：`main.cpp` 支持 `argv[1]` 打开真实媒体（1.5s 后 `openFile`，`setStartupMedia` 让恢复会话让位）；`RCP_SNAPSHOT=<png>` 在 T1/T2 两帧 grab 后 quit。
- 命令（worker+模型须在 `out\bundle\runtime`）：`RCP_SNAPSHOT=<png> .\player_app.exe "<真实视频路径>"`，T1/T2 要留足 worker 出字幕时间（≈20-40s）。
- **硬性要点**：真实字幕验证**不能设 `RCP_NO_CAPTION`**（会跳过 worker → 无字幕）。
- ✅ trace 佐证：`RCP_TRACE=<log>` 记录 `openFile -> 路径`、`reposition host/video/content/box` 矩形。
- ⚠️ 偶发现象：一次运行报「字幕错误」（workerError→setAsrStatus），同命令重跑成功；无残留 worker 进程，属偶发，重试即可。

### 两个字幕路径核查（✅ 结论）
- 实际渲染仅一条：worker → MainWindow `onPartial/onFinal` → `updateOverlay()` → Qt `CaptionLabel` 叠加层（demo 与真实媒体同走此路）。
- `CaptionController::overlayChanged/currentAssEvents`（src/captions/CaptionController.cpp）+ `MpvPlayer::showSubtitleOverlay/clearSubtitleOverlay`（src/player/MpvPlayer.cpp 200-215，mpv `osd-overlay` ass-events）为 P6 遗留**全仓库无调用者死代码**；连同 CaptionStateMachine/AssEscaper 构成废弃的第二条字幕实现（违反 AGENTS.md「同一职责只允许一个实现入口」）。
- ❌ 拟删除上述文件（含单测）收敛单一路径——**用户拒绝删除确认，未删除任何文件**。下一步等用户决定：a) 保留文件仅断开 MainWindow 接线；b) 维持现状；c) 授权后再删。

## 补充（2026-09-04 晚）：「字幕错误」稳定复现排查——worker IPC 连接超时窗口过脆

### 问题描述
- 用户实测：打开 G 盘提干课，**视频正常播放但稳定报「字幕错误」、字幕行数 0、已识别时长 00:00**。此前我误判为"偶发"（同命令重跑有成功），被用户纠正"我一测试就是字幕错误"。

### 排查路径（❌ → ✅）
- ❌ 怀疑 worker 模型加载慢：实测 `caption_worker.exe --servername X` 独立启动 **0.73s 即监听**，模型是在 OpenMedia 后才加载，排除。
- ❌ 怀疑残留 worker 进程锁模型：当前无残留进程，排除（但曾发现我测试遗留的 caption_worker 占着 runtime 内 tst_err.txt，导致 MSI 打包失败——教训：测试进程务必确认 Kill 干净，测试文件勿写进 runtime）。
- ✅ **根因**：`WorkerSupervisor::tryConnect` 固定 50×100ms=**5s** 内未连上 worker IPC 即永久报「字幕错误」；且每次重试**销毁重建 QLocalSocket**，可能打断正在建立的 pipe 连接。worker 冷启动（杀软扫描/磁盘慢/主线程忙）监听耗时可能远超 5s，用户环境稳定复现；我这边偶发（3 连跑全成功）。
- ✅ **修复**（654d7c2）：复用同一 socket 重连、超时放宽至 **60s**（600×100ms）、worker 在连接前退出则提前报错、最终错误带上最后一次 socket error；MainWindow workerError 处理器加 rcpTrace 输出真实错误消息。
- ✅ **验证**：G 盘提干课真实播放 → 运行状态=**运行中**、字幕 9 行、画面 partial+final 双行字幕正常、无 workerError。
- ✅ 后续诊断方法：先 `Select-String trace.log -Pattern 'workerError|Ready|MediaOpened|字幕'` 拿具体错误（6 类错误里只有带消息才可知根因）；UI 只显示「字幕错误」不显示消息，靠 trace。

> 本轮一个关键纠偏：**不得只依赖 OCR/描述判断按钮有无**——参考稿右组的「字幕轨」按钮曾因 OCR 漏读被误判不存在。凡涉及控件有无/图标归属，必须回到 `05_Single_HTML_Frontend_Reference.html` 源码核对 `<button>` 标记。
