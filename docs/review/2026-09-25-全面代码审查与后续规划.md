## 0. 结论

当前代码能打开视频、播放，并在画面上显示字幕，适合做演示，但**离 PRD/技术方案定义的 MVP 还差很多**：

1. **状态文档与事实不符**：`implementation-status.md` 写着"T0001–T0272 完成 / RELEASE READY"，
   但 `03_Detailed_Development_TODO.md` 291 项里没有一项勾选；同一文件又写"P0 进行中、P1–P9 待启动"。
2. **实时字幕并不实时**：worker 从 0 秒开始全速转录整个文件，seek、倍速、暂停、切音轨都不会通知 worker；
   partial 没有时间戳，却被无条件显示，所以灰字对应的往往是"未来"或"开头"的音频。
3. **前端是"像素复刻壳"**：外观接近参考稿，但很多控件不执行任何功能（假开关），默认启动就注入虚构的
   播放列表、历史和字幕；全局 `outline:none` 且没有任何 `:focus` 规则，违反 AGENTS.md 的 hover/focus-visible 要求。
4. **基础设施缺口大**：没有 SQLite 持久化、ActionRegistry、单实例、文件关联、CI、日志脱敏、模型清单；
   `resources/CMakeLists.txt` 引用不存在的 `resources/models/model-bundles.json`，干净检出很可能 configure 失败。

## 1. 实时字幕管线（最高风险）

### 1.1 严重缺陷

| # | 问题 | 证据 | 修复方向 |
|---|---|---|---|
| 1 | 后台识别用 `QtConcurrent::run([this]…)` 捕获裸 `this`，`m_running` 非原子；Shutdown 后对象析构而任务仍在跑 → 竞态/UAF | `src/worker/IpcServer.cpp:118-126`、`IpcServer.h:50-53` | 专用线程 + CancellationToken + join，析构前停止 |

### 1.2 场景推演

- **跳到 2 小时视频中段**：worker 仍从 0 秒顺序识别，得等前一小时识别完才有中段字幕；这期间 overlay 的 final 回退逻辑会显示开头的句子。
- **切换音轨**：启动时固定传 `audio_track=-1`，worker 永远识别第一条音轨。
- **倍速/暂停**：只作用于 mpv；worker 继续全速读完整个文件。
- **rclone 网盘文件**：FFmpeg 不限提前量地顺序读完整个文件，与 mpv 的随机读抢带宽，会撑满 VFS 缓存。

### 1.3 方案偏离总表（摘要）

已实现：分进程 + QLocalSocket、客户端安全分帧、Zipformer2-CTC + VAD + SenseVoice 双引擎、SRT 原子写。
缺失或偏离：generation 隔离（7.4）、seek flush/pre-roll（7.6）、以播放头为基准的 30–120 s 提前量调度（7.7）、
pause/speed 同步、aid→ff-index 映射（6.6）、有界队列/背压（7.8，`BoundedQueue` 只在单测里用）、
partial 200 ms 限频与去重、稳定 segment ID、2.5 s 终稿超时与修订（`SegmentAssembler` 未接入）、
Lite/Balanced 档位、过载检测与自动降级（8.6）、zh/en/auto 语言（SenseVoice 固定 `auto`）、
CaptionCoordinator 状态机（9.1）、SQLite 字幕缓存（9.5）、VAD 参数与方案不一致（8.3）。

### 2.3 已确认的逻辑 bug

- 连续播放到最后一项时，`onPrevNext(1)` 被 `qBound` 夹回当前行，**重新播放最后一集**，形成循环（`MainWindow.cpp:1808-1812,1910-1918`）。
- 开启"连续播放"时 `onMediaEnded` 提前 return，**自动导出 SRT 永远不会执行**（`MainWindow.cpp:1914-1919`）。
- `positionChanged` 同时触发两个槽，每次都执行两遍 `updateOverlay()`，且两份 finals 各做一次线性扫描（`MainWindow.cpp:168,221-226`）。
- GUI 心跳定时器在正式版里一直运行，每 500 ms 写 trace，并 `new int` 且不释放（`MainWindow.cpp:232-238`）；Waveform 空闲时也每 70 ms 唤醒一次（`UiKit.h:263-274`）。
- 日志写入完整路径和字幕正文，违反隐私规则（`MainWindow.cpp:1557,1583,1736`）。

### 2.4 hover / focus-visible / 无障碍

- `MainWindow.cpp:66` 全局 `* { outline: none; }`，全部 QSS 中没有一条 `:focus` 规则 → 键盘焦点完全不可见。
- 搜索框、ComboBox、路径输入框、自绘 `Switch` 没有 hover 样式；`Switch::paintEvent` 不绘制焦点。
- 没有 `setAccessibleName` / `setTabOrder`；图标按钮只有 tooltip；当前字幕没有暴露给屏幕阅读器（方案 9.3 要求）。
- 快捷键是硬编码的窗口级 `QShortcut`（`MainWindow.cpp:275`），在搜索框里输入 `S/R/F`、空格会误触发播放器动作。

参考稿 `05_Single_HTML_Frontend_Reference.html:73-76` 有统一的紫色 focus ring，Qt 版应对齐。

### 2.5 结构问题

`MainWindow.cpp` 2115 行，同时承担窗口框架、播放控制、mpv 直接调用（绕过 `MpvPlayer`）、设置、历史、播放列表、
字幕状态、导出、demo 数据和 QSS。字幕有两套状态（`m_captionCtl` 与 `m_finals/m_partialText/m_overlayFinalText`），
显示读一份、导出读另一份。

## 5. 后续规划

原则：先修"诚实度"和"地基"，再做核心差异化（真实时字幕），然后把前端从"像素壳"变成"能用的播放器"，
最后才是集成与发布。每一步都能独立构建、演示和验收。

```
阶段 A 止血/重新基线 ─▶ 阶段 B 字幕管线重做 ─┬─▶ 阶段 D 持久化与基础设施 ─▶ 阶段 E Windows 集成与发布
                                           │
                        阶段 C 前端纠偏（可与 B 并行，C1 不依赖 B）
```

### 阶段 B：实时字幕管线重做（L，核心差异化）

目标：字幕跟随播放头，seek/切音轨/倍速/暂停都正确；任意时刻屏幕上的 partial/final 对应当前播放位置附近的音频。

- B1 协议加固：两端统一 `FrameDecoder`；必填字段校验；`Unknown` 类型；每条命令 ack/error；事件保留原始 generation。
- B2 worker 重构：`IpcController`（解析/ack）→ `AudioDecoder`（seek、flush、PTS sample clock、RAII）→
  `DecodeAheadScheduler`（按播放头/倍速限制 30–120 s，暂停休眠）→ `BoundedQueue<PcmChunk>` →
  `OnlineAsrWorker`（Zipformer，200 ms 限频 + 去重）+ `VadSegmenter`（稳定 segment ID）→
  `FinalAsrWorker`（SenseVoice）→ `SegmentAssembler`（2.5 s 超时、修订）→ 有界出站队列。
- B3 主进程 `CaptionCoordinator`：合并 `WorkerSupervisor` 的会话控制与 `CaptionController`；完整状态机
  （Disabled/Starting/Running/Seeking/Suspended/Error）；唯一时间线（有序，二分查询）；aid→ff-index 映射；
  seek/换片/换轨/换语言/换档位时 generation+1 并清 partial。
- B4 生命周期：心跳超时判定、自动重启退避、Job Object、`closeEvent` 优雅关闭。
- B5 Lite/Balanced 档位、语言 zh/en/auto、过载检测与自动降级。
- 验收：用固定测试视频做 E2E——播放到 30 min 处 seek，3 s 内出现该位置字幕；切音轨后字幕换成对应语言；
  4x 倍速下字幕仍对齐；杀掉 worker 后 5 s 内自动恢复。
