# ADR-0007：字幕渲染采用单一 Qt 路径（CaptionLabel）

- 状态：已接受（2026-09-27，经用户授权按外部审查建议执行）
- 关联：ADR-0003（worker 分进程）、技术实现方案 §9.3、`docs/review/2026-09-25-全面代码审查与后续规划.md` §6 决策 1、`docs/implementation-status.md` 2026-09-04「两个字幕路径」记录

## 背景

P6 期按技术实现方案 §9.3 实现了 mpv `osd-overlay` + ASS 渲染链（CaptionController →
`MpvPlayer::showSubtitleOverlay`，AssEscaper 转义，CaptionStateMachine 管显示态）；P7 像素复刻后，
实际渲染改走 Qt `CaptionLabel`（worker → MainWindow onPartial/onFinal → updateOverlay → CaptionLabel）。
2026-09-04 核查确认 mpv 路径已无调用者，构成废弃的第二条字幕实现；用户当时拒绝了物理删除。
外部审查（§2.5、§6.1）进一步指出：双状态源（`m_captionCtl` 与 `m_finals/m_partialText`）导致
"显示读一份、导出读另一份"，违反「同一职责只允许一个实现入口」。

## 决策

1. **唯一字幕渲染路径 = Qt `CaptionLabel`**（视觉已经用户按参考稿逐像素验收）。
2. mpv `osd-overlay` 路径（CaptionController 的 overlay/ASS 输出、`MpvPlayer::showSubtitleOverlay/
   clearSubtitleOverlay`）与仅做显示态包装的 `CaptionStateMachine`、`AssEscaper` 定性为**死代码**：
   授权前不接线、不维护、不得新增调用者；物理删除须待用户明确授权（2026-09-04 用户曾拒绝删除）。
3. **字幕时间线只保留一份**：以 CaptionController 的 finals 时间线为唯一数据源；MainWindow 内
   `m_finals` 等影子状态在阶段 B3（CaptionCoordinator）落地时移除，显示与导出必须读同一份。
4. 带实时字幕的截图采用「mpv 视频帧 + CaptionLabel 合成」方案（Qt overlay 不会进入 mpv 截图），
   在阶段 C3 实现截图功能时落地。
5. 本 ADR 记录对技术实现方案 §9.3（mpv ASS overlay）的**已接受偏差**；若未来回归 mpv 路径，
   须以新 ADR 取代本决策并重做视觉验收。

## 后果

- 正面：消除双路径与双状态源；视觉沿用已验收实现；带字幕截图方案明确。
- 负面：技术方案 §9.3 与实现长期偏离（由本 ADR 收口）；死代码在获授权删除前继续存在于仓库。
